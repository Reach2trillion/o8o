# ABJ Android app

`mobile/` builds **ABJ**, an optional Android app for the ABJ SkinCare sales team. It is a thin
[Capacitor 8](https://capacitorjs.com/) shell: its WebView opens the Sale Check phone screen straight from the
Odoo server (`<ABJ_SERVER_URL>/odoo/abj`, module `checkinme_sales_activity`). Screens, check-ins, GPS
and photos are the same web code as in the browser, so a server update reaches every phone without a new APK.

The app adds what a browser cannot do well:

| Feature | How |
|---|---|
| Push notifications | Firebase Cloud Messaging (`@capacitor/push-notifications`), sent by the Odoo server (planned visits, follow-up reminders, Odoo messages) |
| Receipt printing | native plugin `AbjNative`: Bluetooth Classic printers (SPP), network printers (raw TCP, port 9100), Android print framework |
| Back button | goes back in the screen history (`@capacitor/app`); at the start screen it sends the app to the background |
| Downloads | Odoo PDF reports and exports are saved to *Downloads* and opened |
| Offline page | an ABJ page with a *Try again* button when the server cannot be reached |

GPS (`navigator.geolocation`) and the camera (`<input capture>`) need no plugin: the WebView provides them
and asks Android for the permissions.

## App or installed web app (PWA)?

**Use the PWA first.** On iPhone it is the only option (Safari > Share > *Add to Home Screen*, iOS 16.4+), and on
Android, Chrome > *Install* gives the same screens, web push and Bluetooth printing (Web Serial on Chrome 138+,
Web Bluetooth for BLE printers) with nothing to build or update.

Install the Android app instead when:

* the receipt printer does not work from Chrome: older Chrome without Web Serial, Bluetooth Classic printers that
  Chrome cannot open, or network (Wi-Fi/Ethernet) printers on port 9100 that no browser can reach;
* notifications must arrive reliably: FCM high-priority messages with a 24 h lifetime still arrive when Chrome
  has been closed or put to sleep by battery optimisation;
* the phone is a shared, kiosk-like device that should open straight on the sales screen, without browser UI.

Do not install both on the same phone: it would receive every notification twice (web push to the PWA and
FCM to the app). Uninstall one of them.

## Folder layout

| Path | Content |
|---|---|
| `package.json`, `package-lock.json` | exact Capacitor versions (`@capacitor/core`, `cli`, `android` 8.5.3, `push-notifications` 8.1.3, `app` 8.1.2) |
| `capacitor.config.ts` | app id, name, server URL, user agent `ABJApp/<version>`; reads the environment variables below |
| `www/index.html` | offline page (the app never shows a local copy of the screens) |
| `resources/icon.png`, `resources/icon-foreground.png` | 1024 px sources of the launcher icons (made with the Odoo module icons) |
| `scripts/make_icons.py` | regenerates the launcher icons in `android/app/src/main/res/mipmap-*` from `resources/` |
| `android/` | Android Studio / Gradle project (generated by `npx cap add android`, then customised) |
| `android/app/src/main/java/com/abj/app/` | `MainActivity`, `AbjNativePlugin` (printing), `AbjDownloads`, `AbjWebViewClient` (offline page) |

Generated, not committed: `node_modules/`, `android/capacitor-cordova-android-plugins/`,
`android/app/src/main/assets/{public,capacitor.config.json,capacitor.plugins.json}`, build outputs,
`google-services.json` and keystores. `npx cap sync android` recreates the generated files.

## Build settings

| Variable | Used by | Default | Meaning |
|---|---|---|---|
| `ABJ_SERVER_URL` | `cap sync` | `https://erp.example.com` (placeholder, with a warning) | Origin of the Odoo server: scheme, host and optional port only. A trailing `/` is removed; a path, query or fragment is refused. Use `https` (plain `http` is accepted for local tests only; GPS does not work on `http`). |
| `ABJ_APP_ID` | `cap sync`, Gradle | `com.abj.app` | Android `applicationId`. Must match the Firebase Android app. The Java package stays `com.abj.app`. |
| `ABJ_APP_VERSION` | `cap sync`, Gradle | `version` of `package.json` | `versionName`, also sent in the user agent (`ABJApp/1.0.0`) |
| `ABJ_VERSION_CODE` | Gradle | `1` | `versionCode` (must increase for every update installed over a previous one; CI uses the run number) |
| `ABJ_KEYSTORE_FILE`, `ABJ_KEYSTORE_PASSWORD`, `ABJ_KEY_ALIAS`, `ABJ_KEY_PASSWORD` | Gradle | none | release signing; without them `assembleRelease` produces an unsigned APK |

The server URL is written into the APK by `npx cap sync` (`android/app/src/main/assets/capacitor.config.json`):
run the sync again after changing it. One APK serves one Odoo server.

## Build locally

Requirements: Node.js 22+, JDK 21, Android Studio (or the Android SDK command-line tools) with *Android SDK
Platform 36*.

```bash
cd mobile
npm ci
export ABJ_SERVER_URL=https://erp.example.com     # your Odoo server
npx cap sync android                              # npm run sync
npx cap open android                              # npm run open: Android Studio, then Run
```

Command line instead of Android Studio:

```bash
cd mobile/android
./gradlew assembleDebug                           # gradlew.bat on Windows
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

(`npm run build:debug` runs the sync and `assembleDebug` in one go.) For push notifications, put the
`google-services.json` of your Firebase project in `mobile/android/app/` before building (see below);
without it the app works with notifications disabled.

Debug builds allow remote debugging of the WebView: open `chrome://inspect` on a computer with the phone
connected over USB.

## Build in GitHub Actions

`.github/workflows/abj-android.yml` runs on every push that touches `mobile/**` (or the workflow) and on demand
(*Actions > ABJ Android app > Run workflow*, optional input `server_url`). It installs Node 22, JDK 21 and the
Android SDK, runs `npm ci`, `npx cap sync android` and `./gradlew assembleDebug`, and uploads the APK as the
artifact `abj-debug-<run>`. When the signing secrets exist it also builds `assembleRelease` and uploads
`abj-release-<run>`. The `versionCode` is the run number.

Repository settings (*Settings > Secrets and variables > Actions*), all optional:

| Kind | Name | Value |
|---|---|---|
| Variable | `ABJ_SERVER_URL` | e.g. `https://erp.example.com` (the `server_url` input of a manual run overrides it) |
| Variable | `ABJ_APP_ID` | only if not `com.abj.app` |
| Secret | `GOOGLE_SERVICES_JSON` | `base64 -w0 google-services.json` (macOS: `base64 -i google-services.json`) |
| Secret | `ANDROID_KEYSTORE_BASE64` | `base64 -w0 abj-release.jks` |
| Secret | `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD` | the keystore password, key alias and key password |

Without `GOOGLE_SERVICES_JSON` the build still succeeds (push disabled, with a warning). Secrets are written to
the runner only for the build and deleted afterwards; they are never committed.

## Firebase (push notifications)

The Odoo server sends notifications through Firebase Cloud Messaging (HTTP v1 API). One Firebase project serves
one app id.

1. **Create the project.** <https://console.firebase.google.com> > *Add project* (e.g. "ABJ"). Google Analytics
   is not needed.
2. **Add the Android app.** *Project settings > General > Your apps > Add app > Android*. Package name: the
   `applicationId` (`com.abj.app`, or your `ABJ_APP_ID`). Nickname "ABJ". The SHA-1 certificate is not needed
   for messaging.
3. **Download `google-services.json`** from the same page. Local builds: copy it to
   `mobile/android/app/google-services.json` (git-ignored). CI: store its base64 as the secret
   `GOOGLE_SERVICES_JSON`. Rebuild the app.
4. **Check the API.** *Project settings > Cloud Messaging*: "Firebase Cloud Messaging API (V1)" must be
   *Enabled* (default for new projects). The legacy server key is not used.
5. **Create a service account for Odoo.** In the [Google Cloud console](https://console.cloud.google.com) of the
   same project: *IAM & Admin > Service accounts > Create service account* (e.g. `odoo-abj-push`), role
   **Firebase Cloud Messaging API Admin**, then *Keys > Add key > Create new key > JSON*. (Firebase's
   *Project settings > Service accounts > Generate new private key* also works, but that account has far
   broader rights.) Keep this file secret; it is not part of the app.
6. **Give it to Odoo.** *Settings > Sale Check > ABJ Mobile App > Android App Notifications (Firebase)*: upload
   the JSON key and save; the project id is shown when it is valid.
7. **Test.** Open the app on a phone, log in and allow notifications (Android 13+ asks once). The phone appears
   under *Sale Check > Configuration > ABJ App Devices*. Then use *Send a test notification to me* (Odoo
   settings, or the Settings screen of the app). Deliveries and errors are listed in *Sale Check > Reporting >
   Push Logs*.

Notifications use the channel `abj_default` ("ABJ", high importance) and the white map-pin status bar icon.
Tapping one opens the related visit or record in the app.

## Printers

Receipts are drawn by the web client as an image (Khmer text cannot be printed in ESC/POS text mode) and sent
as ESC/POS raster commands, which nearly all 58 mm and 80 mm thermal receipt printers understand.

**Bluetooth printers (most portable printers).**

1. Turn the printer on. On the phone: *Settings > Connected devices > Pair new device*, choose the printer
   (PIN usually `0000` or `1234`).
2. In ABJ: gear icon > *Printer* > Bluetooth, *Choose printer*. Android 12+ asks for the *Nearby devices*
   permission once. Paired devices are listed, likely printers first. BLE-only printers are not listed
   (use the Chrome PWA, which supports them through Web Bluetooth).
3. Pick the paper width (58 mm = 384 dots, 80 mm = 576 dots) and *Print test page*: it must show the Khmer
   line "សួស្តី ABJ" and a full-width ruler.

**Network printers.** Give the printer a fixed IP address, then choose the network transport and enter the IP
(port 9100 unless the printer manual says otherwise). The phone must be on the same network.

**System printing.** Uses the Android print dialog: Wi-Fi printers with a print service (Mopria, vendor
plugins) or *Save as PDF*.

Troubleshooting: *cannot connect* means the printer is off, out of range, or still connected to another phone
(Bluetooth printers accept one connection at a time). *Permission denied*: allow *Nearby devices* under
Android *Settings > Apps > ABJ > Permissions*. Garbled or cut lines: check the paper width setting.

## Google Play

* **Signing.** Create an upload key once and keep it safe (losing it blocks updates):
  `keytool -genkeypair -v -keystore abj-release.jks -alias abj -keyalg RSA -keysize 2048 -validity 10000`.
  Add it to the CI secrets above. Google Play also requires an Android App Bundle: run
  `./gradlew bundleRelease` (same signing variables) and upload `app/build/outputs/bundle/release/app-release.aab`.
  With *Play App Signing*, the key above is only the upload key.
* **Policy risk.** Google Play rejects apps that are mostly a website in a WebView ("minimum functionality" /
  webview spam policy). Native printing and push help but do not guarantee approval. For an internal sales
  team, prefer private distribution: a *managed Google Play* private app for your organization, an MDM, or
  installing the signed APK directly.
* **Store listing.** The Data safety form must mention location (check-ins, foreground only), photos, and the
  device token used for notifications; the privacy policy must cover the Odoo server.
* `targetSdk` and `compileSdk` are 36, `minSdk` 24 (Android 7.0).

## Limitations

* **Google sign-in does not work in the app:** Google blocks OAuth in embedded WebViews. Users log in with their
  Odoo login and password (set one for users who only used Google so far).
* **Do not install both the app and the PWA** on one phone: duplicate notifications (see above).
* Only pages of `ABJ_SERVER_URL` open inside the app; other links (Google Maps, websites) open in the browser.
* The server must be reachable over HTTPS with a valid certificate; GPS needs HTTPS.
* No iOS app: iPhones use the PWA.
* Not yet tested on a physical phone: the CI build compiles the app, but check push, Bluetooth printing and
  downloads on one real device of each model in use before handing the app out.

## Maintenance

* **Icons:** replace `resources/icon.png` / `icon-foreground.png` (1024 px, the foreground on a transparent
  background), then `python3 scripts/make_icons.py` (needs Pillow) and commit the generated `mipmap-*` files.
* **Capacitor updates:** bump the exact versions in `package.json`, `npm install`, `npx cap sync android`, and
  compare `android/` with a freshly generated project (`npx cap add android` in a scratch copy) for template
  changes (Gradle plugin, `variables.gradle`).
